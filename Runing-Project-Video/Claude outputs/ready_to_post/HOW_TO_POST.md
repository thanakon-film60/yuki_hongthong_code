# story_park — พร้อมโพสต์ ตรวจสเปกแล้ว

ตรวจกับไฟล์จริงด้วย ffprobe แล้ว (ไม่ใช่เดาจากชื่อไฟล์): 1080×1920, h264, yuv420p, ไม่มี rotation flag ค้าง — ปลอดภัยทั้ง IG และ FB

## IG Story → ใช้ `IG_Story/story_park_38s.mp4`
ไฟล์เดียว 38.2 วิ อยู่ในลิมิต IG Story (≤60 วิ/การ์ด) โพสต์เป็นการ์ดเดียวได้เลย ไม่ต้องตัด

## FB Story → ใช้ 3 ไฟล์ใน `FB_Story/` ตามลำดับ
FB Story จำกัดสั้นกว่า IG (≤20 วิ/การ์ด) ไฟล์เต็มเลยถูกแบ่งเป็น 3 ท่อน ท่อนละ 12.7 วิ ให้ผู้ใช้อัปตามลำดับติดกัน:
1. `story_park_part1.mp4`
2. `story_park_part2.mp4`
3. `story_park_part3.mp4`

อัปทั้ง 3 ท่อนใน "เซสชันเดียว" (ห่างกันไม่เกินสองสามนาที) เพื่อให้ผู้ชมเห็นเป็นเรื่องเดียวต่อกัน ไม่ใช่โพสต์แยกวันคนละที

## แคปชัน (ถ้าจะใช้)

## ข้อควรระวัง — ไฟล์เก่าในโฟลเดอร์หลักอย่าใช้
ในโฟลเดอร์ `Claude outputs/` (ระดับบน) มี `story_park_part1.mp4` / `part2.mp4` / `part3.mp4` ตัวเดิม
ที่ยังมีบั๊ก typewriter (ข้อความโผล่เต็มประโยคตอนต้นคลิปแล้วค่อยพิมพ์ใหม่) — **ไม่ใช่ตัวที่อยู่ในโฟลเดอร์นี้**
ไฟล์ในโฟลเดอร์ `ready_to_post/` นี้คือตัวที่แก้บั๊กแล้ว (คัดลอกมาจาก `part1-1/2-1/3-1.mp4`) ใช้ชุดนี้เท่านั้น

หมายเหตุความถูกต้อง: รอบที่แล้วบอกว่า "ไฟล์ทับของเดิมทั้งหมด" ซึ่งไม่ตรงกับความจริง — ไฟล์ที่แก้แล้วถูกเซฟเป็นชื่อใหม่ต่อท้าย `-1`
ไม่ได้ทับไฟล์เดิม ไฟล์เก่าที่มีบั๊กเลยยังค้างอยู่ในโฟลเดอร์หลัก โฟลเดอร์ `ready_to_post/` นี้สร้างขึ้นเพื่อตัดปัญหาเลือกไฟล์ผิด
